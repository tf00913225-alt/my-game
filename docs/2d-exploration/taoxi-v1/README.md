## 已確認的首版範圍

所有裝置使用 **9:16**，沿用既有共用 **1080×1920** 邏輯畫布與顯示架構；電腦置中顯示直式遊戲，兩側可用非互動背景，不做 PC 16:9 改造。探索採中等視野：角色清楚，也能看見附近道路與幾間房屋。畫風配合現有創角立繪，景物與地面較簡潔；探索人物略 Q，保留自然手腳與俠客感。

主城與故事頁都有探索按鈕，兩者先進「四象江湖大地圖」選區頁，再由桃溪村入口切換至可走動場景。這是各區獨立切換的架構；首版可玩區域是完整小型桃溪村，包含村口、廣場及民宅周圍。暗色地區不包含各區場景施工。

完成前 5 關且新手教學完成後開放桃溪村。後續黑松林的既定規劃為完成第 19 關後開放，不是打敗第 20 關寨主後；保留這項規劃，但本次不包含黑松林場景製作，也不能把規劃描述成已上線的功能。

首版有 **5 間可入民宅、共 10 個搜尋點、4 男 4 女共 8 款探索外觀**。外觀對應玩家創角選擇。五間民宅採共同室內美術標準；進屋切換獨立室內，出屋回村莊。總量不代表五屋起始全部開放。

移動同時支援點地與虛擬搖桿。靠近村民後顯示「交談」，由玩家點選開始。搜尋獎勵各領一次，離開、重進或重載仍保存領取狀態；一次性搜尋維護暫評低，因不需刷新週期。

村內解鎖混合主線進度及村內交談／線索，維護暫評中，因需管理兩類條件；不是每處都必須同時完成兩類。探索與故事分開，普通交談、看線索不自行推進主線。本次不自行加入商店、戰鬥、支線任務或戶外採集。

## 可逆的工程與內容建議

下列是施工起點，不是歷史已確認決策。施工者先核對程式與故事合理性，採取可逆初值，集中配置並記錄理由，無須再逐件詢問家具或人數。

- A、B 屋起始開放，共 4 點；C 屋由已開區的交談／線索開放，2 點；D 屋採主線條件，2 點；E 屋可採主線加探索條件，2 點。每處列明固定條件，避免循環解鎖或必要線索藏在尚待它開啟的房間。
- 主線條件可參考 `c1_06`「村民求援」與 `c1_16`「寨前情報」，讀過實際故事再選門檻；節點名稱不代表這裡已指定解鎖時點。
- 可先配 3 名村民、6 個獎勵點與 4 個描述／線索點。具體文字、家具及獎勵內容依既有資料設定；物品須有有效 ID，數量採保守初值，不臆造現有物品。已讀線索宜可重讀，解鎖資格不因獎勵已領取而消失。
- 返回建議：室內回原門口附近安全位置，村莊回大地圖，大地圖回進入來源；保留故事進度。這是返回實作預設，不能寫成使用者曾逐項確認。
- 8 款人物可先採四向行走圖，自由斜向移動沿用相鄰面向；向數與動作幀數由現有原型及樣張檢查後記錄。人物素材維護暫評中，因八款均需製作與核對；四向並非使用者已選。

上述維護等級是相對估計，不是工時承諾。

## 正式素材與整合邊界

先看圖並回報三個具體觀察：立繪與場景的筆觸配色、簡潔程度與中央可走空間、略 Q 人物在場景中的比例。概念圖只提供方向，仍須製作適合引擎的場景分層、遮擋、碰撞及角色動作。不可把含介面或示範人物的整張圖當正式背景；暫用素材須標示，方塊、emoji 或不同風格素材不能充作最終美術。

以即時倉庫為準定位 single display／save owner。先前基準的 `js/startup/account-save-repository.js` 可供追查帳號存檔入口；保留 UID 隔離，不另建第二套存檔。發獎與已領取狀態須透過既有負責流程一致提交，失敗不能留下已領但未得獎勵的狀態。

主線 runtime 的提交模式可參考，但故事節點領獎、`startStory`、`advanceDialogue` 不能直接當普通搜尋／村民對話 API。先定位既有展示與背包等負責模組；尚未核實的 owner 不得憑名稱假設。商店未列入首版，不為了重用而新增範圍。
