# Canonical character schema and recovery gate — design only

`users/{uid}/saves/current`: small public envelope with owner, schema, `serverRevision`, `authoritativeStateReady`, materialized snapshot revision/hash/reference and timestamps. Do not append receipt/claim maps to this document. Private canonical records: `serverUsers/{uid}/characters/{characterId}` (element, levels, EXP, skills, quests/progression), `economy/current` (gold/currencies), `inventory/{ownedItemId}` (identity/quantity), `equipment/{ownedItemId}` (ownership and equipped references), `relics/{relicId}` (ownership/level/loadout), `progress/{source}` (Boss/tower/abyss), `claims/{source-period-rewardKey}` (unique claim), `operations/{operationId}` (receipt), and ledger entries partitioned by period. All identity and references are validated in one server-side operation; Firestore transaction limits govern any design that spans documents.

`serverUsers/{uid}/playableSnapshots/{revision}` is a compact materialized projection with all three supported characters and dependent state/claim flags, schema, SHA-256 and source revision. Reads validate hash/schema/owner; no partial snapshot may set ready. Keep potentially large immutable recovery objects outside the hot envelope. Migration candidates (`trusted:false`) stay private and distinct from: (1) explicitly accepted baseline, (2) ongoing authoritative canonical state, and (3) independently retained recovery snapshots. For large candidate bundles prefer immutable Cloud Storage objects plus Firestore metadata after estimating real save sizes; until then the callable rejects oversized bundles. Exempt private raw `backup` and `snapshot` map fields from single-field indexes only after verifying no query uses their nested fields; no index config is activated in this PR.

Before ready=true: create server-owned snapshot history and retention; verify backups cover account, economy, inventory, equipment, relics, progress and claims; define restore point/revision and operator authorization; restore into a fresh revision with an audit receipt; detect corruption by digest; rehearse accidental overwrite, Firestore corruption, cleared localStorage, entirely new phone, stale simultaneous revisions, lost operation response and payment entitlement preservation. Snapshot rollback cannot roll back operation IDs or reopen unique claims. Record outcome and exact snapshot revision used for every recovery.
