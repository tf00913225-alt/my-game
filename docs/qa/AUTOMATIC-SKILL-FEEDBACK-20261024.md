# 自動技能特效樣板

目前沿用 #989／WIND-FLURRY-SAMPLE-20261024。候選開啟正式11個風系主動技能，以及原火焰斬、治療術、岩石壁壘樣板；其餘元素的資料規則可解析，但尚未全面套用或部署。角色大小、我方前後排一致大小、敵方既有景深、精靈圖與玩法保留。遠中近分層只新增在裝飾特效，不再縮小或調暗角色。

## 進遊戲怎麼看

候選通過驗收並更新開發站後，在已學習並裝備技能的角色回合，選「技能」再選相應目標。

- 暴風亂擊選有三個敵人的橫排：看風屑葉片、三下橫掃與最後一下收力；削弱成功才有下沉圈與剩餘回合。
- 火焰斬選一名敵人：看橘紅、向上飄的碎屑與集中爆發。
- 治療術對受傷隊友施放：看綠金柔光向上飄；不震動、不停頓。滿血也沒有恢復SP時不假裝治療成功。
- 岩石壁壘：看實際成功目標的柔光罩。無法套用時不放成功提示；既有護盾／狀態仍依原回合規則消失。

手機影片使用隔離測試隊伍和標示過的固定判定，仍呼叫原正式施放流程，不改玩家存檔。影片與最新狀態以 PR body 為準；尚未部署時，開發站看不到候選。

## 屬性對照

正式屬性優先；屬性缺漏才從名稱／敘述找提示，仍無法判斷就用白色火花。沒有新增玩法屬性或更改技能歸屬。

| 屬性 | 顏色 | 裝飾與方向 |
| --- | --- | --- |
| 火 | 橘紅、淡金 | 火花、餘燼向上 |
| 水／冰 | 藍白 | 水滴感、冰晶碎片向下散落 |
| 風 | 青綠、淡白 | 風屑、葉片橫向捲過 |
| 雷 | 黃白 | 電弧、折線火花 |
| 土 | 褐黃 | 碎石、塵土下落 |
| 光 | 金白 | 上升光點、放射碎光 |
| 暗 | 紫黑 | 柔化暗粒子向中心吸入 |
| 無屬性／不明 | 白 | 通用火花 |

## 自動規則

| 技能資料 | 自動效果 |
| --- | --- |
| 單體傷害 | 集中一次爆裂、短停頓、震動、閃白與收尾 |
| 多目標／橫排／直排 | 按實際目標位置依序；直排按上下，橫排按左右，預設間隔0.1秒；不增加目標或傷害次數 |
| 全體 | 原全體技能本體保留；最後有效命中加範圍衝擊波與短畫面閃光 |
| 高傷害／暴擊 | 增加停頓、震動與碎屑，上限限制避免過猛；不延長原技能Gate |
| 治療 | 綠金上升柔光；沒有震動或停頓，只跟隨實際恢復 |
| 增益／護盾／減傷 | 成功後上升光圈／柔光罩；刷新也須確認本招的成功狀態 |
| 有機率減益 | 只依原成功結果顯示下沉圈，不額外抽機率 |
| 持續傷害／控制 | 沿用正式狀態Owner的持續圖示／標記與到期清理；已啟用且正式成功的燃燒另有少量上升粒子。設定也保留中毒配色，但不因此新增中毒玩法 |

目前風系11招與原三個跨類型樣板以外仍維持原效果。規則已能分析其他／新增技能；全面啟用時切換 `automatic.rolloutAll`，不用逐招指定。缺少專用圖的技能只補通用裝飾，不偽造精靈圖或玩法狀態。

## 同一份設定

`config/battle-vfx-feedback.json` 是唯一手感設定。`defaults` 是基礎，接著套屬性表、類型表，最後套 `skills` 的個別覆蓋；個別未填欄位保留預設。修改後走正常建置與驗證。原停頓、震動、命中閃白、逐幀停留、拖尾等每個數字的完整說明，沿用 [暴風亂擊手感表](WIND-SWEEP-FEEL-20261024.md#一份設定就能調)。

新增設定如下：

| 設定 | 調大／調小的效果 |
| --- | --- |
| `automatic.enabled` | 開關自動判斷；原個別明確覆蓋仍可保留 |
| `automatic.previewSkills` | 目前驗收的四種；不是每招必填的特效表 |
| `automatic.rolloutAll` | true依規則套全部非被動技能；目前false，避免一次改完整套技能 |
| `automatic.elements.*.colors` | 依屬性更改粒子、圈與尾跡顏色；不重畫技能本體 |
| `automatic.elements.*.hints` | 資料缺漏時可辨識的名稱／敘述詞；不改遊戲屬性 |
| `automatic.elements.*.shape/direction` | 粒子樣式與上升／下落／橫掃／內吸方向 |
| `automatic.types.*` | 各技能類型可覆蓋下列表內相同數字，例如治療停頓與震動固定為0 |
| `blendMode`（screen） | screen保留加亮風感；plus-lighter可選。手機對照screen長停頓較少，但不代表已達60fps |
| `criticalScale`（1.25） | 大：暴擊停頓／碎屑更強；小：與普通命中差別較小 |
| `maxStopMs`（75） | 大：高傷害最多停得更久；小：更俐落，硬上限100毫秒 |
| `supportMs`（480） | 大：治療／增益柔光收得較慢；小：較快 |
| `supportRise`（0.5） | 大：柔光上升較遠；小：較貼近角色 |
| `shieldOpacity`（0.16） | 大：新柔光罩較明顯；小：更透明；不改既有護盾圖或減傷值 |
| `depth.*.size` | 大：該層粒子較大；小：較細碎；不改角色 |
| `depth.*.speed` | 大：該層飄得快、較快收尾；小：更慢 |
| `depth.*.blur` | 大：該層邊緣柔化較寬；小：較銳利，最多4；快取光暈不逐幀重算模糊 |
| `depth.*.opacity` | 大：該層較實；小：更淡 |
| `depth.*.cap` | 大：容許更多同層裝飾；小：更乾淨。近景額外掠過硬上限2；原技能本體不受減量影響 |
| `depth.assignment` | 可把某類裝飾改到far／mid／near；沒指定用中景。個別技能也能覆蓋 |
| `performance.canvasDpr`（1） | 大：粒子更細，但更耗能；小：較省。角色與原圖不縮小 |
| `performance.adaptive` | true負載較高時自動減少裝飾；false保留設定數量 |
| `performance.slowFrameMs`（28） | 小：更早判定負載偏高；大：較晚減量 |
| `performance.slowFrames`（4） | 小：更快反應；大：多等幾次慢幀才減量 |
| `performance.minQuality`（0.6） | 大：至少保留較多裝飾；小：高負載時能再減量 |
| `performance.step`（0.1） | 大：每次減量較明顯；小：漸進調整 |
| `performance.spriteShadow`（false） | true恢復本體額外即時陰影，但較耗能；false保留加亮混色與快取粒子光暈 |
| `automatic.status.dotParticleCap`（8） | 持續傷害小粒子全場上限；小更省，硬上限12 |
| `automatic.status.dotPerState`（2） | 每個狀態最多幾枚小粒子；硬上限2 |
| `automatic.status.dotSizePx`（3） | 大：持續粒子較大；小：較細 |
| `automatic.status.dotDurationMs`（1000） | 大：上升較慢；小：較快 |
| `automatic.status.dotRisePx`（18） | 大：上升較遠；小：貼近身體 |
| `automatic.status.dotElements` | 持續傷害種類使用哪個屬性的粒子配色 |

關閉整個模組用頂層 `enabled:false`；遊戲中開關介面 `FourSymbolsHitFeedback.setEnabled(false/true)`。關閉會清除新瞬時特效、附加小粒子與新回合數文字，原技能圖、狀態和傷害保持。

## 驗證與限制

四種樣板的正式Core施放、治療不震動、成功／未成功提示、被阻擋／無關狀態／同值增益刷新、原目標與Gate、狀態到期及畫布清理均有針對性證據。原圖未改、我方大小一致、敵方景深未改。

景深是新增裝飾的分層：技能本體仍原DOM中景，底層畫布在技能本體後，最多兩枚近景粒子在本體前；不移動既有角色或背景。持續狀態附屬粒子沿既有狀態節點生命週期，不設新回合計時器。

目前手機仍有長幀；不得把自動減量、桌面測試或整段平均FPS當成穩定60fps。最新原片、解碼幀間隔、版本及CI由PR body記錄；未達效能／人類美術Gate前維持候選，不宣稱全部完成。


## 多階段演出公式（2026-10-24候選）

**演出 = 技能類型的五段節奏 × 屬性的動作特色 × 真正命中的力道；個別覆蓋最後套用。**

五段固定責任是「蓄勢 → 發射／展開 → 原定時刻命中 → 受力／餘波 → 淡出回位」。不新增傷害次數，不改Core、SP、目標、狀態機率／回合與原Gate。美術素材能銜接時優先保留；只有素材本身不適合才更換，不因需要彈道而全部重做。

| 現有資料 | 自動選用演出 |
| --- | --- |
| 治療／增益／護盾 | 聚光上升／展開包覆，不套用攻擊停頓與受力 |
| 全體風攻擊 | 區域旋渦：擴張、變向漂移、命中、反向捲動、消散 |
| 其他全體攻擊 | 範圍展開與衝擊，避免憑空增加多枚飛彈 |
| 既有animationStyle為projectile，或名稱／敘述含飛、箭、彈、投、射 | 從正式施法者立繪中心飛到真正受擊者；多目標各自瞄準，按既有命中節奏到達 |
| 其他多目標／橫排／直排 | 依正式目標方向橫掃或縱掃，原成功結果才接命中回饋 |
| 其他單體物理 | 收緊蓄勢、突擊擴張、短促受力回位 |
| 其他法術／資料不足 | 通用湧出與消散，缺漏不報錯，不猜玩法 |

既有專屬motionPhases／彈道優先，不疊第二個transform Owner。已驗收的普通攻擊、暴風亂擊與火焰斬保留既有編排。狂風術／風焰術改用獨立單目標12格素材，由原per-recipient路徑投影到三人，玩法範圍仍為tri／row。

火向上噴發、水冰推湧回落、風有較強擺動、雷短促、土偏沉重、光上升、暗收束；支援技能優先壓掉攻擊受力。位移與縮放使用transform，顯隱用opacity，粒子維持原有上限。

### 調數字的效果

所有新增數字仍在同一份 `config/battle-vfx-feedback.json` 的 `choreography`。依序套defaults → archetypes → elements → skills個別覆蓋。

| 數字 | 調大／調小的結果 |
| --- | --- |
| anticipation | 大：蓄勢較久、飛行段更短急；小：較早出手。命中時間不變 |
| settle | 大：命中後保持較久、最後淡出更快；小：較早進入消散 |
| startScale | 大：起手較飽滿；小：先壓縮再展開。1為已fit好的最大本體 |
| tailScale | 大：尾段保留體積；小：收尾縮得更多 |
| travel | 大：非實際飛彈的起手偏移較多；小：較接近原位。真正彈道的距離由施法者／目標位置決定，不用此數字假造距離 |
| drift | 大：命中後漂移／旋渦折返更明顯；小：更集中 |
| rise | 正數偏向上湧，負數偏向落下；絕對值越大越明顯 |
| recoilPx | 大：真正命中後受力位移更明顯；小：較輕，不移動正式站位 |
| tiltDeg | 大：受力歪斜更明顯；小：較穩。支援技能固定不歪斜 |
| recoilMs | 大：受力回位更慢；小：短促，仍不得跨出原技能期限 |

非彈道動作依可見alpha中心縮放，漂移上限按可見alpha的剩餘空間計算，不把透明padding當成可用淨空。真正彈道允許在施法者與目標間移動，終點仍對齊原命中位置；不是宣稱整段飛行都留在目標的HUD安全框。

`choreography.enabled=false`可關閉新動作公式、保留既有回饋；整套模組開關仍為最上層enabled。無新runtime fetch。內部介面新增choreographyFor、choreographyTrack、projectileTrack、reactionTrack，原V143生命週期取消／重測量保留currentTime。

目前是工程候選，不代表所有元素已完成手機驗收。風起雲湧候選已新增整個實際目標區的3個龍捲漫遊、原立繪同源前後投影交錯，以及僅真命中啟動的受風搖晃；整批最新手機影片與效能／人類美術驗收仍以PR及實機證據為準。


### 風起雲湧的全區風場

`fieldScene` 是同份設定的區域演出參數，只套用已啟用的全體風技能。原六個正式目標／成功狀態不變，最多3個可見龍捲代表在全部目標立繪形成的區域漫遊；不是三次傷害或少打三人。

- `maxFunnels`：同時大龍捲數量，上限3，增加會更密集。
- `sizeRatio`／`maxScale`：龍捲相對區域寬度／高潮放大幅度；受整個戰場區域限制，不放大角色。
- `paths`：每個龍捲各段的橫／直位置，0到1對應區域兩端；改動可控制繞行方向。
- `phaseOffsets`／`phaseScales`：各段出現時機與體積；全段仍在原2600ms期限內。
- `occlusionStep`：前後交錯間隔占整段的比例；小會較頻繁，大則每段較久。
- `swayPx`／`tiltDeg`／`swayCycles`：真正命中後受風位移、歪斜角度和來回次數。傷害／暴擊按既有有界力道縮放，最後回到原位。

前後分層使用同一正式立繪投影，沒有複製角色卡、HUD或新增遊戲實體；原畫面立繪只暫時隱藏，原大小與敵景深不變。兩層的顯隱互補，不同時畫兩個角色。來源更新同步；死亡、換角色／paint、關閉模組、離場或清理即恢復。閱讀視窗開啟時沿用既有 suppression，投影隱藏且原立繪恢復，不蓋住視窗。減少動態時不啟用風場投影／搖晃。
