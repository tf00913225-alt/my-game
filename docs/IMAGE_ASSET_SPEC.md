# 《四象江湖傳》圖片素材正式導入規範

本文件是新圖片素材進入正式遊戲資產時的權威規範。除非專案負責人日後明確修改，所有 GPT、Claude、Codex、人工開發與素材整合作業都必須遵守。

## 一、適用範圍

適用於所有新加入正式遊戲的點陣圖片，包括但不限於：

- 角色／怪物／BOSS 立繪
- UI 圖片、背景、封面、按鈕與裝飾
- 裝備、技能、道具、秘寶 Icon
- VFX、Sprite Sheet、狀態動畫
- 副本、塔、戰鬥與其他遊戲內圖片

SVG 等向量資產不強制轉成 WebP；本規範主要管理 PNG、JPG、JPEG 等點陣圖片。

## 二、正式遊戲資產一律使用 WebP

1. 自本規範生效後，所有新點陣圖片在進入正式遊戲 `assets` 或被正式程式引用前，原則上一律轉成 `.webp`。
2. 原始 PNG／JPG 可以作為母圖保存在素材庫、`assets-library` 或 `assets/inbox`，但不得因方便而直接成為新的正式 runtime 資產。
3. 正式遊戲不得同時無必要保留同內容的 PNG/JPG 與 WebP，避免重複佔用容量。
4. 若特定技術流程確實不支援 WebP，必須先確認原因並在修改回報中明確記錄；不得自行跳過本規範。

## 三、預設必須採無損 WebP

1. 新圖片預設使用 **lossless WebP**。
2. 未經專案負責人明確同意，不得為了縮小檔案而自行改成有損 WebP。
3. 透明圖片必須完整保留 Alpha channel。
4. 轉檔不得改變原始像素尺寸、長寬比、畫布大小、透明區域、裁切範圍或圖片方向。
5. 不得產生可見色偏、黑邊、白邊、透明邊緣污染、鋸齒增加、細節消失或其他畫質退化。

## 四、VFX／Sprite Sheet 額外限制

VFX、Sprite Sheet、循環狀態動畫除了符合一般圖片規則外，還必須：

- 保持原始畫布寬高完全一致。
- 保持格數、幀排列、每幀位置與透明 padding 完全一致。
- 不得自動 trim、crop、resize 或重新排版。
- 不得因轉 WebP 改變動畫讀取座標或幀數。

若無法證明上述條件成立，該素材不得取代原檔進入正式遊戲。

## 五、正式使用前的必要驗證

每張／每批新圖片轉成 WebP 後，至少必須確認：

1. WebP 可以正常解碼與載入。
2. 像素尺寸與原始母圖一致。
3. 長寬比一致。
4. 需要透明背景時，Alpha 透明資訊完整。
5. 沒有意外裁切、縮放、旋轉或畫布改變。
6. UI／立繪／Icon 不得因轉檔而改變畫面尺寸、定位或 `object-fit` 行為。
7. VFX／Sprite Sheet 的格數、幀位置與播放結果一致。
8. 所有 HTML／CSS／JavaScript／registry／manifest／資料表等引用已同步指向正確 `.webp` 路徑。
9. 不得留下造成 404、broken image 或舊副檔名失效的引用。

**未完成上述驗證，不得宣稱素材已正式導入，也不得刪除仍被正式程式依賴的舊檔。**

## 六、禁止為轉檔順手改 UI 或美術

WebP 轉檔本身不得順手修改：

- UI 尺寸或版面
- 圖片顯示比例
- 角色／怪物構圖
- 裁切範圍
- VFX 幀數與動畫節奏
- 美術內容、色調或特效

若需要上述變更，必須視為另一項獨立需求處理。

## 七、舊圖片的處理方式

本規範對「之後新增或重新導入」的圖片立即生效。

既有已在正式遊戲使用的 PNG／JPG **不因本規範而要求一次性全面轉換**。舊素材遷移必須另開獨立任務／分支，分批確認引用、透明度、UI、VFX 與載入結果後再取代，避免大規模回歸。

## 八、素材庫與正式遊戲的界線

- `assets-library`／`assets/inbox`：可保存原始母圖與待處理素材。
- 正式遊戲 runtime assets：新點陣圖片原則上只使用已驗證的 WebP。
- 從素材庫導入正式遊戲時，必須先完成 WebP 轉換與本文件要求的驗證，再更新正式引用。

## 九、核心永久原則

**新圖片：先轉 WebP → 驗證無損與透明度／尺寸／幀資料 → 更新正式引用 → 驗證遊戲載入與畫面 → 才能正式使用。**

任何代理或開發者不得以「瀏覽器本來就支援 PNG」、「先放進去之後再轉」或「容量不大」為理由跳過此流程。
