# Offline authority policy — online-first release decision, not activated

P4 first-release decision (owner-confirmed 2026-10-19): implement online settlement for ordinary battle earnings first, preserving existing reward values and unrestricted daily challenges. Offline play retains the same UID's local progress/candidate and conflict protection; reconnect must not silently promote that candidate or replace a newer authoritative revision. Offline reward tickets, including their expiry, batch count and aggregate allowance, are deferred beyond this first release. High-value claims still require online authority. This is the implementation target, not evidence that any pending writer or complete Cloud Save is activated.

The current game remains locally playable; this policy defines the eventual transition and does not assert server reward writers exist. `ONLINE_REQUIRED`: paid rights, store purchases/limits, unique daily/weekly claims, Boss first-clear grants, tower milestone/chest grants, abyss first-clear/chest grants, rare relic ownership, high-value synthesis/reforge and refund/revoke. The existing local paths must remain labeled provisional until trusted writers exist.

Hero acquisition has a separately authorized bounded online source (user decision 2026-10-12; `HERO_SYSTEM_V1.md`): observed server Taipei login dates and a UID-bound chapter-one ticket/ordered-intent source, with immutable unique rights/receipts/ledger. Offline local dates, chapter flags and restored saves never award or reopen Hero rights. Ordinary chapter combat remains Client simulation; the ticket does not certify battle victory. This limited Hero source neither activates generic offline settlement nor publishes/adopts a complete character save.

`OFFLINE_LIMITED` (future offline earning scope): normal patrol/dungeon battle, ordinary EXP/gold/drop and ordinary quests. Client animates and simulates locally; a future server-issued attempt/ticket carries UID, source, cap, expiry, nonce and operation ID. On reconnect the backend settles only eligible bounded rewards and returns receipts, with duplicate protection and expected revision. Expired, consumed or missing tickets become conflict/review, not automatic upload. The approved P4 first release requires connectivity for settlement of these rewards; local offline progress remains provisional and cannot authorize cloud earnings.

`OFFLINE_ALLOWED`: battle animations/VFX, read-only story, UI navigation, sound, auto-battle preference and device cache. They may reset on another phone without affecting durable entitlements.

Three evaluated modes: A (block high-value offline progress), B (pre-issued limited tickets), and C (accept client-only ordinary settlement). The approved first release uses online authority for high-value claims and online settlement for ordinary rewards, with provisional offline local progress/conflict protection. B remains future work; C does not authorize cloud settlement. Future offline expiry/caps and supported reward paths require an inventory of game reward writers, an explicit product decision and emulator abuse tests before activation. Do not introduce a daily/hourly challenge limit or change reward values under this decision. No every-action Cloud Function or authoritative timestamp comparison.
