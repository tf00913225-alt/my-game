# 秘寶獲取／碎片／Boss／四象塔養成系統

狀態：本文件描述 `js/relic-progression-drop-system.js` 的正式初始平衡與維護邊界。

## 1. Runtime owner 與既有架構

- `js/60-team-relic-system.js`：秘寶戰鬥效果、秘寶目錄、裝備中的秘寶、秘寶頁基礎 UI。
- `js/gameplay-boss-tower-system.js`：玩法中心、個人／世界 BOSS、四象塔 100 層與其既有進度。
- `js/relic-progression-drop-system.js`：本文件涵蓋的唯一 owner，負責秘寶專屬碎片、通用碎片、秘寶精華、突破石、Boss 定向掉落、塔養成／保底、碎片合成與素材強化。
- 背包沿用 `v132AddItemToInventory / v132ConsumeStackItem / v132RunInventoryTransaction`，不建立第二套庫存。
- 持久化沿用目前 UID 主存檔；新進度記錄放在 `player.relicProgression`。不新增秘寶專用 localStorage save key。
- 不包裝 `winBattle / loseBattle / v132LaunchDungeonBattle / saveGame`。Boss／塔完成以現有公開玩法進度狀態與安全 pending receipt 對帳。

## 2. 核心循環

- Boss＝定向刷指定秘寶專屬碎片。
- 四象塔＝秘寶精華、通用碎片、突破石與里程碑自選箱。
- 專屬碎片＝合成秘寶的主要來源。
- 通用碎片＝2:1 補洞；每件最多替代 50 個專屬碎片，因此至少要先取得 50 個專屬碎片。
- 秘寶精華＝常態升級材料。
- 秘寶突破石＝高難 Boss、塔 Boss／每 10 層的進階材料。
- 自選箱＝25／50／75／100 層永久首達保底。

## 3. 稀有度

固定沿用：白 → 藍 → 紫 → 橙 → 桃紅 → 四象。

初始權重：白 40、藍 30、紫 18、橙 8、桃紅 3、四象 1。

Boss 小池先依上述權重選擇候選秘寶，再依該品階的碎片落點門檻判定是否真正掉碎片：白 100%、藍 90%、紫 72%、橙 50%、桃紅 28%、四象 12%。這些都是集中設定，不散落在戰鬥程式。

## 4. Boss 單次數量與材料

| 難度 | 專屬碎片（抽中時） | 秘寶精華 | 通用碎片額外掉落 | 突破石額外掉落 | 模擬單場時間 |
|---|---:|---:|---:|---:|---:|
| 普通 | 2–4 | 10–16 | 4%，1 | 0 | 2.0 分 |
| 困難 | 3–5 | 18–28 | 6%，1–2 | 0 | 2.5 分 |
| 地獄 | 4–7 | 30–44 | 8%，1–2 | 10%，1 | 3.0 分 |
| 特殊 | 5–8 | 42–60 | 12%，1–3 | 18%，1–2 | 3.5 分 |

模擬單場時間只用於平衡估算，不會改變戰鬥計時；正式遊戲沒有 Boss 每日次數限制，因此實際取得速度主要受玩家戰力與單場耗時影響。

個人 Boss：Lv20–40＝普通、Lv50–70＝困難、Lv80–90＝地獄、Lv100＝特殊。世界 Boss 的階段難度依階段提高，完成後的第 4 階段重打以特殊難度估算。

Lv70+ 個人 Boss 首殺與世界 Boss 最終階段首殺另保底突破石 ×1。

## 5. Boss 定向池

單 Boss 僅 1–3 件，不使用全秘寶大池。正式初始配置由 `RELIC_BOSS_DROP_TABLE` 管理。例如：

- 熾焰狼王：青嵐羽符／烈陽神珠。
- 烈焰巨魔王：烈陽神珠／九龍神火罩。
- 深淵水靈王：乾坤玉壺／寒泉玉珮。
- 絕冰魔君王：鎮魂古鐘／天罡戰旗。
- 世界終焉神魔皇：天罡戰旗／回天寶輪／萬象歸元盤。

`萬象歸元盤` 目前戰鬥 runtime 尚未開放，但最高難世界 Boss 可以先累積它的四象碎片；合成／裝備仍會被 `runtimeReady` 安全阻擋，直到本體正式完成。

## 6. 四象塔 100 層

目前實際塔層是 100 層，不新增不存在的 150／200 層。

- 普通層：秘寶精華。
- 每 5 層但非 10 層：秘寶精華＋通用碎片（3／4／5，依樓層區間）。
- 每 10 層：較多秘寶精華＋通用碎片（8／9／10）＋突破石 ×1。
- 25 層永久首達：藍階以下碎片自選箱 ×1（自選 15 碎片）。
- 50 層永久首達：紫階以下碎片自選箱 ×1（自選 20 碎片）。
- 75 層永久首達：橙階以下碎片自選箱 ×1（自選 20 碎片）。
- 100 層永久首達：桃紅階以下碎片自選箱 ×1（自選 25 碎片）。

完整 1–100 層一週可取得的秘寶養成保底總量（不含四個永久首達箱）：秘寶精華 2,556、通用碎片 128、突破石 10。通用碎片 128 足以支援一次「50 專屬＋100 通用」的最大補洞，但無法繞過至少 50 專屬碎片規則。

永久里程碑使用 `player.relicProgression.majorMilestoneClaims` 記錄；週塔本身仍沿用既有 `claimedFloors`。既有玩家若在本系統上線前歷史最高已超過某永久里程碑，初始化時視為已通過，避免一次性追溯發放造成經濟突增。

## 7. 合成與強化

### 合成

- 固定 100 專屬碎片。
- 2 通用碎片＝1 指定碎片。
- 最多替代 50 個，因此 `ownedSpecificFragments >= 50` 才能使用通用碎片補足。
- 100 專屬：可合成。
- 99 專屬：不可單靠專屬直接合成；若符合 50% 規則且通用足夠，可用通用補 1。
- 50 專屬＋100 通用：可合成。
- 49 專屬＋任意通用：不可合成。
- 已持有秘寶不會刪除多餘碎片，碎片保留供未來擴充。

### 強化

目前秘寶正式上限是 Lv20，因此不擅自建立 Lv30／40／50 規則。

- 升級消耗秘寶精華：`20 + 目前等級 × 6`。
- Lv10 → Lv11 需要額外突破石 ×1。
- 現有金幣-only 公開強化入口改由本 owner 接手；秘寶戰鬥效果本體不變。

## 8. 防重複與失敗恢復

Boss／塔挑戰開始前會先將本次隨機結果與「獎勵前物品數量」寫入 `player.relicProgression.pending`。勝利後以現有 gameplay progress 判定戰果，再把缺少的差額原子加入背包。

因此可處理：

- 戰鬥結束後、秘寶材料尚未寫入就 reload：依 pending 補發。
- 材料已寫入但 pending 尚未清除就 reload：以 before-count＋reward-count 判斷已發過，不再重複累加。
- 背包滿：pending 保留，整理背包後可再次對帳。
- 戰敗／中途離開：玩法進度沒有勝利變化，不發獎並清理 pending。
- 存檔寫入失敗：保留／恢復上一份 pending 狀態，不把失敗當成功。

## 9. 取得速度估算

以下為目前設定的「最佳已存在定向來源」期望值；模擬時間是平衡假設，不是玩家實際秒數。`50` 代表已達可使用通用碎片最大補洞的門檻，`100` 代表完全不使用通用碎片。

| 品階 | 代表來源 | 平均 50 專屬 | 平均 100 專屬 | 約 60 分鐘／日 |
|---|---|---:|---:|---:|
| 白 | 目前沒有正式白階秘寶 | — | — | 不臆造內容 |
| 藍 | 玄武靈印／Lv50 個人 Boss | 56 分 | 111 分 | 約 1–2 日 |
| 紫 | 九龍神火罩／世界 Lv80 最終階段 | 60 分 | 120 分 | 約 1–2 日 |
| 橙 | 天罡戰旗／世界 Lv100 最終階段 | 81 分 | 162 分 | 約 2–3 日 |
| 桃紅 | 回天寶輪／世界 Lv100 最終階段 | 385 分（6.4h） | 769 分（12.8h） | 約 7–13 日 |
| 四象 | 萬象歸元盤碎片／世界 Lv100 最終階段 | 2,692 分（44.9h） | 5,385 分（89.7h） | 約 45–90 日 |

四象的設計重點是：單次抽中仍掉 5–8 片，不做「超低率＋只掉 1 片」；同時 50 專屬門檻與塔通用碎片提供可預期長期保底。

### 30／60／120 分鐘 Boss 養成材料期望值

只計連續刷同難度 Boss，不把塔層耗時硬猜進模型：

| 難度 | 30 分鐘：精華 / 通用 / 突破 | 60 分鐘 | 120 分鐘 |
|---|---|---|---|
| 普通 | 195 / 0.6 / 0 | 390 / 1.2 / 0 | 780 / 2.4 / 0 |
| 困難 | 276 / 1.08 / 0 | 552 / 2.16 / 0 | 1,104 / 4.32 / 0 |
| 地獄 | 370 / 1.2 / 1.0 | 740 / 2.4 / 2.0 | 1,480 / 4.8 / 4.0 |
| 特殊 | 437 / 2.06 / 2.31 | 874 / 4.11 / 4.63 | 1,749 / 8.23 / 9.26 |

同一時間內的「指定專屬碎片」依 Boss 小池與品階而不同。以最佳來源為例，60 分鐘期望約：藍 54、紫 50、橙 37、桃紅 7.8、四象 1.1。這也是為什麼通用碎片只做補洞而不做主要來源。

## 10. 未來擴充

新增秘寶時理想只需要：

1. 在既有秘寶 catalog 新增 relic definition。
2. 本 owner 會自動產生該 relic 的碎片 item definition。
3. 在 `RELIC_BOSS_DROP_TABLE` 將 relic id 加到 1–3 個 Boss 小池。
4. 沿用既有 rarity。
5. 在原秘寶 catalog 設定 iconPath／美術。

不需要修改 Boss AI、戰鬥核心或新增大量 if/else。
